# ADR 0003: Flat JSON trace and a self-contained HTML viewer

- Status: accepted
- Date: 2026-11-03

## Context

A failing seed is only useful if a developer can understand what happened.
Logs from several nodes interleaved in a terminal are hard to follow. We want
a visual timeline that works in CI artifacts, in a PR comment link, and
offline.

## Decision

- A trace is a flat, ordered list of events (`send`, `deliver`, `drop`,
  `timer`, `crash`, `restart`, `pause`, `resume`, `partition`, `heal`,
  `skew`, `log`, `emit`, `violation`). `send`, `deliver` and `drop` share a
  message ID so the viewer can draw arrows.
- Node state snapshots are attached to the event after which they were taken.
- The viewer is one HTML file with the trace embedded as JSON, inline CSS and
  JavaScript, and no external requests. It is generated by `viewer.Write`.

## Consequences

- A failing CI run can upload `trace.html` as an artifact; anyone can open it
  without installing anything.
- The same file can be hosted unchanged. (Phase 5 stores traces in a private
  S3 bucket and serves them through short-lived presigned links.)
- Very long traces (hundreds of thousands of events) will need windowing in
  the viewer. Simulations that fail usually fail early, so this is deferred.
- The trace is also the determinism check: its SHA-256 is the run's
  fingerprint.
